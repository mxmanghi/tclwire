TclWire

TclWire is a Tcl application server being shaped around small, composable server implementations. The current runtime focuses on HTTP while the threading, routing, logging, and configuration model settle.

Current Runtime

The application entry point is tclwire.tcl. By default it starts one HTTP listener on 127.0.0.1:8990.

tclsh tclwire.tcl

Use --httpport and --host to choose a different endpoint.

tclsh tclwire.tcl --host 127.0.0.1 --httpport 8080

HTTP Serving

The HTTP service serves ::tclwire::CApplication. Its default routing behavior is static file serving from the configured document root.

For GET and HEAD requests, paths are resolved under the active document root. Existing application routes can still return dynamic responses before the static fallback is used.

The current default service set is intentionally restricted to HTTP. HTTPS, FTP, and proxy code may still exist in the repository, but they are not part of the default startup path while the TclWire architecture is being reorganized.

Document Roots

The active document root is selected in this order:

  • --docroot /path/to/root
  • TCLWIRE_DOC_ROOT
  • /tmp/tclwire

If the configured document root does not exist, TclWire creates it and seeds it with the built-in index content. If the directory already exists, TclWire leaves its contents untouched. Document roots are retained when the server exits.

tclsh tclwire.tcl --docroot /var/tmp/tclwire-site

Threading Model

The master thread owns the listening sockets. When a client connects, the HTTP service asks ::tclwire::ThreadMaster for an idle worker thread.

The accepted socket channel is transferred to the selected worker with thread::transfer. The worker configures the channel for nonblocking binary I/O, installs readable events, and serves the connection until it closes.

Workers receive the parsed runtime configuration from the master, including the active document root. Connection open and close events are recorded by the master-side connection database.

Command Line

tclsh tclwire.tcl \
  ?--host address? \
  ?--httpport port? \
  ?--service protocol:port? ... \
  ?--docroot path? ?--ftproot path? \
  ?--logfile path? \
  ?--startservers protocol[,protocol,...]|all? \
  ?--quiet? ?--debug?
Option Purpose
--host Bind services to a specific local address. Default: 127.0.0.1.
--httpport Set the HTTP listener port. Default: 8990.
--service Add an explicit service entry such as http:8080.
--docroot Set the root directory used by HTTP static file serving.
--ftproot Set the FTP root for future FTP service runs. It is not created during HTTP-only startup.
--logfile Set the request log path. Default: /tmp/tclwire.log.
--quiet Suppress listener startup messages.
--debug Enable verbose diagnostic output.

Environment

Variable Purpose
TCLWIRE_DOC_ROOT Default document root when --docroot is not supplied.
TCLWIRE_FTP_ROOT Default FTP root when --ftproot is not supplied.
TCLWIRE_DEBUG Enable debug output before command-line parsing.
TCLWIRE_HTTPS_CERT_FILE Path to an HTTPS certificate for future HTTPS service work.
TCLWIRE_HTTPS_KEY_FILE Path to an HTTPS private key for future HTTPS service work.

Project Direction

The active architecture is moving toward a master process that owns listeners and dispatches accepted channels to worker threads. Each worker runs a server instance and reports lifecycle, errors, and request logging back to the master.

The next useful steps are to generalize the HTTP worker script into a reusable server-worker template, rename CApplication to an HTTP-specific application class, and continue separating protocol-neutral runtime support from HTTP-specific behavior.
