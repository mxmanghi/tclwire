TclWire

TclWire is a Tcl application server shaped around small, composable server implementations. The current runtime starts HTTP by default and again supports selectable FTP and HTTP proxy services alongside the shared threading, logging, and configuration model.

Current Runtime

The application entry point is tclwire.tcl. By default it starts one HTTP listener on 127.0.0.1:8990. FTP and proxy listeners are available when selected from the command line.

tclsh tclwire.tcl

Use --httpport and --host to choose a different HTTP endpoint.

tclsh tclwire.tcl --host 127.0.0.1 --httpport 8080

Use --startservers to start the default listeners for multiple protocols. Repeat --service with the same selected protocols when explicit port pairs are needed.

tclsh tclwire.tcl --startservers http,ftp,proxy
tclsh tclwire.tcl --startservers all
tclsh tclwire.tcl --startservers http,ftp,proxy --service http:8080 --service ftp:2121 --service proxy:8992

Services

The HTTP service serves ::tclwire::CApplication. Its default routing behavior is static file serving from the configured document root.

For GET and HEAD requests, paths are resolved under the active document root. Existing application routes can still return dynamic responses before the static fallback is used.

The FTP service exposes the configured FTP root and supports interactive file operations through the FTP worker thread. The HTTP proxy service accepts proxy-form HTTP requests and CONNECT tunnels, with proxy authentication support for protected test targets.

HTTP remains the default service set. FTP, FTPS, HTTPS, and proxy listeners are implemented but must be requested with --startservers or --service. Secure listeners require the configured TLS certificate and key files to be present.

Document Roots

The active document root for HTTP and HTTPS is selected in this order:

  • --docroot /path/to/root
  • TCLWIRE_DOC_ROOT
  • /tmp/tclwire

If a configured HTTP application document root does not exist, TclWire creates it and seeds it with the HTML documentation generated by utils/md2html.tcl. Existing document roots are left unchanged. Document roots are retained when the server exits.

tclsh tclwire.tcl --docroot /var/tmp/tclwire-site

The FTP root defaults to the document root unless TCLWIRE_FTP_ROOT or --ftproot is supplied. When an FTP or FTPS listener is selected, TclWire creates the FTP root if necessary and seeds it with a welcome file.

tclsh tclwire.tcl --startservers ftp --ftproot /var/tmp/tclwire-ftp

Threading Model

The master thread owns the listening sockets. When a client connects, the selected service asks ::tclwire::ThreadMaster for an idle worker thread for that protocol class.

The accepted socket channel is transferred to the selected worker with thread::transfer. The worker configures the channel for nonblocking binary I/O, installs readable events, and serves the connection until it closes.

Workers receive the parsed runtime configuration from the master, including the active document root. Connection open and close events are recorded by the master-side connection database.

Command Line

tclsh tclwire.tcl \
  ?--host address? \
  ?--httpport port? \
  ?--httpsport port? ?--ftpport port? ?--ftpsport port? ?--proxyport port? \
  ?--service protocol:port? ... \
  ?--docroot path? ?--ftproot path? \
  ?--certfile path? ?--keyfile path? ?--noftp-user-check? \
  ?--logfile path? \
  ?--startservers protocol[,protocol,...]|all? \
  ?--quiet? ?--debug?
Option Purpose
--host Bind services to a specific local address. Default: 127.0.0.1.
--httpport Set the HTTP listener port. Default: 8990.
--httpsport Set the HTTPS listener port when HTTPS is selected. Default: 9443.
--ftpport Set the FTP listener port when FTP is selected. Default: 8991.
--ftpsport Set the implicit FTPS listener port when FTPS is selected. Default: 990.
--proxyport Set the HTTP proxy listener port when proxy is selected. Default: 8992.
--service Add an explicit service entry such as http:8080, ftp:2121, or proxy:8992. May be repeated; entries still need to be selected by --startservers.
--startservers Select the default service entries to start. Use a comma-separated list such as http,ftp,proxy or all.
--docroot Set the root directory used by HTTP static file serving.
--ftproot Set the root directory exposed by FTP and FTPS listeners.
--noftp-user-check Disable system user verification for FTP login.
--certfile Set the TLS certificate file used by HTTPS and FTPS listeners.
--keyfile Set the TLS private key file used by HTTPS and FTPS listeners.
--logfile Set the request log path. Default: /tmp/tclwire.log.
--quiet Suppress listener startup messages.
--debug Enable verbose diagnostic output.

Environment

Variable Purpose
TCLWIRE_DOC_ROOT Default document root when --docroot is not supplied.
TCLWIRE_FTP_ROOT Default FTP root when --ftproot is not supplied.
TCLWIRE_DEBUG Enable debug output before command-line parsing.
TCLWIRE_HTTPS_CERT_FILE Path to an HTTPS certificate for future HTTPS service work.
TCLWIRE_HTTPS_KEY_FILE Path to an HTTPS private key for future HTTPS service work.

Project Direction

The active architecture uses a master process that owns listeners and dispatches accepted channels to worker threads. Each worker runs a server instance and reports lifecycle, errors, and request logging back to the master.

The reintroduced FTP and proxy services share the same selectable-service startup path as HTTP. The next useful steps are to keep consolidating protocol-neutral worker support, rename CApplication to an HTTP-specific application class, and continue separating shared runtime support from protocol-specific behavior.
